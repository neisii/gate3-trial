# 주문 처리 미니 시스템

## 이 저장소를 읽는 법

[AI-DLC 하네스(naroo)](https://github.com/neisii/harness-naroo) 0.2.0을 출시하기 전에 점검용으로 쓴 시험 저장소입니다. 게이트웨이 세션 하나가 AI 실무자 세션들에게 작업을 나눠 맡기고, 사람은 게이트(청사진 승인·병합 등)에서만 결정했습니다. 코드는 작은 예제이고, 볼 것은 진행 기록입니다.

읽는 순서:

1. [작업목록.md](./작업목록.md) — 실무자에게 맡긴 작업
2. 아래 PR 표 — 작업이 main에 들어간 순서
3. [위임기록.md](./위임기록.md) — 누가 무엇을 왜 정했는지(사람 원문, 게이트웨이의 승인·보류와 근거)

| PR | 내용 |
|---|---|
| #2 | W0 뼈대 |
| #3 | W2 일별 매출 집계 |
| #4 | W3 상태별 알림 문구 |
| #5 | W2PC 매출에 부분취소 반영(W1 브랜치로) |
| #6 | W3PC 부분취소 알림 문구(W1 브랜치로) |
| #7 | W1 부분취소 + 후속 두 건을 main으로 |
| #8 | 위임기록 |

작업목록에는 일부러 작업 사이의 겹침을 넣어 두었습니다. W1이 공통 코드에 `부분취소`를 더하면 W2(매출)와 W3(알림)이 영향을 받습니다. 실무자들은 이 의도를 모른 채 시작했습니다. 이 겹침이 어디서 드러나 어떻게 처리됐는지, 시험 판정과 고칠 거리는 하네스 저장소의 [관문 3 실전 기록](https://github.com/neisii/harness-naroo/blob/0.2.0/design-notes/tasks/release-0.2.0/gate3-관측기록.md)에 있습니다.

청사진·완료보고서(`docs/`)는 하네스 규칙상 커밋하지 않아 이 저장소에 없습니다.

## 이 코드에 대해

Python 3(3.9 이상) 표준 라이브러리만 쓴다. 설치할 패키지는 없다.

## 구성

| 모듈 | 내용 |
|---|---|
| `orders/codes.py` | 주문 상태 공통 코드 `주문상태`(`주문`·`결제`·`취소`·`부분취소`). 상태 코드는 이 모듈에만 둔다 |
| `orders/models.py` | `품목`(상품명·수량·단가), `주문`(주문id·주문날짜·품목목록·상태·취소품목목록·환불금액), `주문.금액()`, `주문.부분취소()` |
| `orders/repository.py` | `주문저장소`: JSON 파일 하나에 저장·불러오기 |

- 단가와 금액은 원 단위 정수다.
- 주문 id는 문자열이고 주문을 만드는 쪽이 넘긴다.
- 주문 날짜는 `datetime.date`이고 JSON에는 `YYYY-MM-DD`로 저장한다.
- 주문을 만들 때 상태를 반드시 넘긴다(기본값 없음).
- 취소품목목록·환불금액은 부분취소 기록이다. 만들 때 넘기지 않으면 빈 목록·0이다.

## 실행법

실행 진입점은 없고, 파이썬에서 가져다 쓴다. 저장소 루트에서:

```sh
python3
```

```python
from datetime import date
from orders import 주문, 품목, 주문상태, 주문저장소

o = 주문("A-001", date(2026, 11, 21), [품목("볼펜", 2, 1500)], 주문상태.결제)
o.금액()                     # 3000

저장소 = 주문저장소("orders.json")
저장소.저장([o])             # orders.json에 쓴다
저장소.불러오기()            # [주문(...)]. 파일이 없으면 []
```

저장 파일 형식:

```json
[
  {
    "주문id": "A-001",
    "주문날짜": "2026-11-21",
    "품목목록": [
      {
        "상품명": "볼펜",
        "수량": 2,
        "단가": 1500
      }
    ],
    "상태": "결제"
  }
]
```

### 부분취소

결제된 주문에서 품목 줄 일부를 취소한다. 품목목록 안의 위치(0부터)로 고른다.

```python
o = 주문("A-002", date(2026, 11, 21),
         [품목("볼펜", 2, 1500), 품목("공책", 1, 3000)], 주문상태.결제)
o.부분취소([1])              # 3000 (이번 환불 금액)
o.상태                       # 주문상태.부분취소
o.품목목록                   # [품목(상품명='볼펜', 수량=2, 단가=1500)]
o.취소품목목록               # [품목(상품명='공책', 수량=1, 단가=3000)]
o.환불금액                   # 3000
o.금액()                     # 3000 (남은 품목의 합)
```

- 취소한 줄은 품목목록에서 빠져 취소품목목록으로 옮겨진다(원래 순서 유지).
- 환불 금액은 취소한 줄들의 수량×단가 합이다.
- 다음 경우는 `ValueError`로 거절하고 주문을 바꾸지 않는다: 상태가 `결제`가 아님(이미 `부분취소`인 주문 포함), 위치가 없음, 정수가 아닌 위치(`1.5`·`1.0`·`"1"`·`True`·`False` 등), 위치를 dict나 목록이 아닌 단일 값으로 넘김, 범위 밖·음수 위치, 같은 위치 중복, 모든 줄을 고름.

취소 기록(취소품목목록·환불금액)이 있는 주문에만 `취소품목목록`·`환불금액` 키가 저장된다. 부분취소하지 않은 주문의 형식은 위와 같다.

```json
[
  {
    "주문id": "A-002",
    "주문날짜": "2026-11-21",
    "품목목록": [
      {
        "상품명": "볼펜",
        "수량": 2,
        "단가": 1500
      }
    ],
    "상태": "부분취소",
    "취소품목목록": [
      {
        "상품명": "공책",
        "수량": 1,
        "단가": 3000
      }
    ],
    "환불금액": 3000
  }
]
```
